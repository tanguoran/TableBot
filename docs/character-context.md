# 共享角色上下文与自动恢复

启动 `./wsl.ps1` 后，自主模式默认开启。Unity 不在 Play 时等待实时场景上线。聊天与自主规划使用同一个 `CharacterContext` 实例和同一份 `persona.md`。

输入文字并按 Enter 提交，或提交 `/image` 时：

1. 清空旧的待执行队列，让尚未返回的旧计划失效，停止自己的当前自主动作。
2. 进入 `waiting`，聊天获得优先权；回复期间不恢复自主规划。
3. 回复完成后开始计算安静时间，默认 30 秒。
4. 期间再提交一条对话，计时重新从这次回复结束开始。
5. 安静时间到且实时场景在线，重新读取共享上下文并规划后续活动。

计时依据提交的消息和回复结束；CLI 当前没有检测尚未按 Enter 的输入草稿。

`/auto status` 显示 `mode`、`enabled`、`chat_active` 和 `resume_in_seconds`。`waiting` 表示为对话让出控制或等待空闲恢复；`paused` 和 `off` 都不会自动恢复。

以下情况保持暂停：

- `/auto pause`、`/auto off`。
- 直接说“停下”“别动”“不要自己动”“关闭自动模式”等明确指令。Unity 停止结果未确认时会明确说明。
- Unity 鼠标/Esc 手动接管，以及已检测到的其他 MCP 控制或场景会话变化。

用 `/auto resume`、`/auto on` 或直接说“继续活动”恢复。明确关闭后再闲聊不会重新开启。退出 CLI 停止自主系统。

可选 `.env` 配置：

```ini
JARVIS_AUTO_ENABLED=true
JARVIS_AUTO_RESUME_SECONDS=30
```

也可用 `python3 -m jarvis --no-autonomous` 本次关闭启动自动行为；`--autonomous` 强制开启。配置更改需重启 CLI。

## 同一份上下文包含什么

- 唯一人设：`persona.md` 的性格、语言和身份规则，两个入口都加载。
- 同一份聊天历史：保留完整工具交互组及有限图片；规划读取其中近期文字，不接收图片 base64。
- 近期共同经历：用户反馈、回复、已采用计划、聊天/自主的实际工具结果。
- 当前意图与执行状态：用户请求是否仍在处理中、拟执行活动、当前动作与待执行队列。
- 控制状态与实时场景：自主是否开启、是否正在聊天、恢复计时及最新 Unity 快照。实际推理继续获取新快照，离线时不会用旧位置当作实时状态。

`planned` 只表示已采用的意图；动作是否完成看工具的 `arrived` / `succeeded`，取消和失败单独记录。已回复的请求标记为 `responded`，不会作为未执行命令反复重放；近期对话仍可影响后续选择，例如“别老盯着书”。

聊天和自主有各自的本次任务规则与输出格式，但角色经历由同一个上下文管理器维护。规划不再固定要求“先观察，再等待”，可以根据人设、对话和近期活动选择动作。此次没有新增动画或活动模板库。

聊天历史仍按完整轮次限制为最多 30 条消息、约 3000 字符目标预算。共享事件最多 32 条，提供给模型时近期事件约 5000 字符、近期对话约 4000 字符；较大的工具数据会保留标注过的片段。思考只进入诊断日志，不进入角色上下文。上下文保存在当前进程内，不写入个人长期记忆，也不读取监控日志作为记忆。

`/clear` 清空聊天和共同经历，控制开关保持原值；若原先开启，会重新等待安静时间后恢复。

## 相关文件

- `persona.md`：唯一的人设文本。
- `jarvis/character_context.py`：共享状态、经历、意图与控制指令识别。
- `jarvis/agent.py`：聊天任务规则与结果写回。
- `jarvis/autonomy.py`：自主任务规则、队列和空闲恢复。
- `jarvis/__main__.py`：默认开启及对话接管入口。

运行 `./monitor.ps1` 可以看到“共享角色上下文”“等待对话空闲后恢复”“自主模式”和规划事件。`-All` 同时显示完整场景输入。
