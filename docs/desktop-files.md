# 真实桌面文件与3D实体

打开 `desktop/ds_desktop/Assets/Scenes/WhaleDesk.unity` 并点击 Play，会自动读取 Windows 的用户桌面与公共桌面，生成对应的文件实体。窗口顶部提供文件数量、分页、同步和整理按钮。

目前实现：

- 读取桌面一级文件和文件夹；文件夹内部不展开到桌面。
- 忽略 `.lnk`、`.url`、`.appref-ms`、`.website`、隐藏/系统条目、`desktop.ini` 和 Office `~$` 临时文件。符号链接/目录联接不展开，OneDrive 占位文件可保留为实体。
- 单击选择，底部显示完整名称与大小；双击通过 Windows 默认程序外部打开。目录由资源管理器打开。程序/脚本也遵循 Windows 的默认打开行为，仅由用户双击触发。
- 文件点击由统一入口消费，不同时触发鲸鱼娘走路；点击空白桌面仍可移动，Esc 仍可停止角色。
- 文件类型决定写实资产、比例和颜色标识；文档/表格/代码使用书册，图片使用相框，文件夹/压缩包/程序使用收纳盒，音频使用金属光盘，视频暂用盒册实体。已有 HQ 资产被制作成独立文件预设，未下载外部素材。
- PNG/JPEG 可显示实际缩略图，缩至最长512像素。其他图片格式使用通用相框；超过16MB、异常尺寸或未在本地下载的云端图片不自动加载内容。
- 不读取文档正文，不自动执行程序，不提供文件移动/重命名/删除操作。

## 布局

首次按文件夹、文件类型、自然文件名顺序排列（例如 notes2 在 notes10 前）。布局围绕角色活动区生成槽位，避开固定装饰；当前场景有6个陈列槽位，超出部分分页展示。文件保持统一尺寸上限，标签采用屏幕空间绘制，不参与碰撞与寻路范围计算。

普通同步保留已有槽位，新文件补空位；点击“整理”重新按类型/名称紧凑排列。分页和整理会等待当前角色动作结束；新实体的槽位被角色占据时延后出现，避免生成在角色脚下。当前页中可见实体才有接近、观察能力。

原来的桌面占位书本、笔记本、便签在 Play 时隐藏；灯、电脑、盆栽、背景等继续保留。编辑模式仍显示原场景，运行时生成真实文件实体。

## 同步

`FileSystemWatcher` 监听新增、删除、重命名、写入及属性变化，约0.4秒合并一批事件；另每5秒核对一次完整目录，重新获得焦点时立即核对。监听回调只排队，Unity主线程更新实体；扫描和图片读取放在后台。

重命名通过 Windows 文件身份保留 ID 和槽位；扩展名变更时替换视觉资产。文件写入更新大小、时间与图片预览。无法确认同一身份的替换文件分配新 ID。目录或文件暂不可读时保留最后确认的条目，根目录错误显示在界面上，并继续重试。

同步独立于模型运行，暂停 auto 也会继续。同步不重建场景、不改变 `scene_session` 或用户接管计数；正在接近/观察的实体被删除或换出当前页时，动作返回失败。

布局缓存位于 `Application.persistentDataPath/DesktopFiles/manifest.json`，包含文件 ID、来源路径和槽位。用户文件不会导入到 Unity Assets，也不写入场景。缓存不包含文件正文。

## 模型状态

`get_desktop_state` 返回：

- `objects`：当前显示的文件实体和固定场景物件。文件的 `object_type` 为 `file`，带 `desktop_file`、文件类别与扩展名标签。
- 每个文件实体的 `file`：文件 ID、名称、扩展名、类别、是否目录、大小、UTC修改时间、本地可用状态。
- `desktop_files`：完整文件目录、总数、当前页、页数、目录版本与同步错误；每条记录的 `visible` 表示是否有当前可交互实体。

物件筛选只作用于 `objects`，文件目录仍保留。隐藏页中的条目不允许直接作为接近/观察目标。真实绝对路径留在 Windows 文件绑定层，模型通过稳定的物件 ID 感知与行动。

## 调整与验证

模型可通过 [通用物品交互](object-interactions.md) 的 `open_external` 打开支持的文档、媒体和文件夹。仅用于用户主动请求，自主规划不打开文件。

场景中的 `08 - Real Desktop Files` 挂载同步与布局组件。类型映射在 `Assets/WhaleDesk/Files/DesktopFileCatalog.asset`，文件预设位于同目录的 `Prefabs`。同步间隔、比例、是否阻挡寻路等可在 Inspector/资产中调整。

菜单 `Whale Desk > Install Real Desktop Files` 可重新挂载功能，通常无需重复安装。`sourceRootsOverride` 与 `storageDirectoryOverride` 是测试入口，正常使用保持为空。

场景验收通过项目 `Temp` 内的独立文件夹执行，覆盖过滤、自然排序、图片、分页、重命名/改类型、修改、新增、删除当前观察目标、脚本绑定、碰撞范围和禁用后恢复。外部打开在测试中校验绑定与调用入口，不自动启动用户文件或程序。

已通过真实 MCP 读取当前桌面的3个实体及可达站位；原有导航、朝向、坐姿、观察、跳跃和取消回归也通过。运行后可用 `./monitor.ps1` 查看模型读取到的文件状态。
