# Markdown 目录知识库使用说明

项目支持把一个 Markdown 目录接入本地 RAG。你用编辑器维护原文，程序负责扫描、切块、建立向量索引和检索。
默认目录为项目根目录下的 `knowledge/`，已放入一份可以编辑或删除的示例资料。

其中 `knowledge/dnd-expansions/` 是保留原始历史的独立知识库子模块，与 `desktop/` 桌面子模块并列；其内部 `ErdaBook/` 是普通资料目录。其余本地笔记默认不提交 Git，但仍参与 RAG 扫描。见 [资料归属说明](../knowledge/README.md) 和 [仓库关系](repository-layout.md)。

聊天可选择本地 Qwen 或 DeepSeek Flash，两者共用此知识库。向量计算仍由本地 Qwen Embedding 完成，切换聊天模型无需重建索引；检索结果交给所选聊天模型回答。DeepSeek 模式仍需运行本地向量服务，配置与验收步骤见 [模型切换说明](model-providers.md)。

## 1. 放入资料并开始提问

可以在 `knowledge/` 中放入 UTF-8 编码的 `.md` 文件，并建立多级子目录。例如：

```text
TableBot/
├── knowledge/
│   ├── 家庭介绍.md
│   ├── 使用说明.md
│   ├── 居家/
│   │   └── 常用物品位置.md
│   └── 兴趣/
│       └── 戏曲资料.md
├── data/
│   └── jarvis.db
└── .env
```

这是组织方式示例，不会自动创建这些个人资料文件。

在项目目录的 PowerShell 中执行：

```powershell
# 首次使用时提前建立索引
.\wsl.ps1 -Action kb-index

# 启动聊天
.\wsl.ps1
```

已有旧 CLI 时先输入 `/quit`，再重新启动，才能加载新增工具。随后可提问：

```text
请根据知识库里的使用指南，告诉我怎样添加新的资料文件，并标出来源。
```

回答应带上原文件和行号，例如 `示例-机器人使用指南.md:L7-L10`。
这是引用格式示意，具体行号以当前原文和检索结果为准。

## 2. 如何编辑和更新

可以使用 VS Code、Obsidian 或其他文本编辑器维护文件。建议每个文件围绕一个主题，用 Markdown 标题划分章节。

| 文件操作 | 下次知识库查询时的处理 |
| --- | --- |
| 新建 `.md` 文件 | 建立新内容的索引 |
| 修改并保存文件 | 替换该文件的旧片段与向量 |
| 删除文件 | 删除缓存中的文件记录和片段 |
| 重命名或移动文件 | 移除旧路径，按新路径建立索引及引用 |
| 文件内容未变 | 复用现有向量 |

**保存后，下一次调用 `search_knowledge` 时自动同步，不需要重启。**
目前没有独立后台文件监听器；没有知识库查询或手动同步时，缓存不会立即更新。

| CLI 命令 | 用途 |
| --- | --- |
| `/kb` | 查看目录、向量模型、当前缓存的文件数和片段数 |
| `/kb-sync` | 立即增量同步，内容未变的文件不重算向量 |
| `/clear` | 清空短期对话，保留原文件与索引 |

`/kb` 展示缓存统计，不表示每次文件改动都已经同步。需要确认修改生效时先执行 `/kb-sync`。

## 3. Markdown 编写示例

```markdown
# 资料主题

说明这份资料讲什么、适用于谁。

## 基本信息

写清楚关键事实，尽量使用完整句子。

## 操作步骤

1. 第一步。
2. 第二步。

## 注意事项

写明限制条件和例外情况。

## 更新日期

2026-11-01
```

文档标题、章节路径和相对文件路径会参与向量计算，返回的正文片段保持原文。
更新日期是你维护的正文信息，系统不会自动据此判断哪份冲突资料更可信。

## 4. 修改目录和检索参数

`.env` 默认配置如下：

```ini
JARVIS_KNOWLEDGE_DIR=knowledge
JARVIS_KNOWLEDGE_TOP_K=4
JARVIS_KNOWLEDGE_MIN_SCORE=0.5
```

- `JARVIS_KNOWLEDGE_DIR`：根目录，递归读取其中的 Markdown。
- `JARVIS_KNOWLEDGE_TOP_K`：每次最多返回的片段数，允许 1–20。
- `JARVIS_KNOWLEDGE_MIN_SCORE`：最低余弦相似度，允许 -1–1；默认 0.5，需结合实际资料评估。

修改 `.env` 后重启 CLI；只改文档正文不需要重启。
以后可以改成自己的目录，WSL 下支持 Windows 盘符路径，例如：

```ini
JARVIS_KNOWLEDGE_DIR=C:/Users/user/Documents/我的知识库
```

盘符路径会在 WSL 中转换成 `/mnt/c/...`，也支持直接填写 WSL/Linux 路径。
当前未实现 UNC 网络路径转换。目录不存在或不可读时会报错，不会把原缓存当成目录已清空来删除。

强制重算当前目录全部文件的向量：

```powershell
.\wsl.ps1 -Action kb-index
```

它保留原 Markdown 文件。更新同名向量模型权重后也应重建索引。

## 5. 代码与数据流

```mermaid
flowchart LR
    Files[Markdown 原文] --> Scan[扫描与内容摘要比较]
    Scan --> Chunks[标题分节与切块]
    Chunks --> Embed[本地向量模型]
    Embed --> DB[SQLite 索引缓存]
    Query[用户问题] --> Tool[search_knowledge]
    Tool --> Scan
    Tool --> Rank[纯向量相似度检索]
    DB --> Rank
    Rank --> Answer[本地模型回答并引用文件行号]
```

### 扫描与同步

[KnowledgeService](../jarvis/knowledge.py) 只从配置目录读取文件，支持多级子目录和大小写不同的 `.md` 扩展名。
隐藏文件、隐藏目录、符号链接及解析后位于根目录之外的文件不纳入索引。

每次查询前读取目录文件，计算 SHA256 内容摘要，与缓存中的摘要、向量模型名和切块版本比较。
仅新增或变化的文件需要重算向量。模型名称或切块版本改变也会触发重建。

变更先在内存中准备，包括全部需要的向量；随后再次核对文件快照，并用一个 SQLite 事务提交更新和删除。
发生读取、编码或向量计算错误时，不发布本次部分更新，当前查询明确报错，不使用旧片段继续回答。
计算向量期间资料再次发生改变时，同步会提示重试。

### 切块与来源

`chunk_markdown()` 识别 `#` 至 `######` 的 ATX 标题，记录标题层级；围栏代码中的标题符号不用于分节。
每节按最多约 1000 字符切成窗口，优先在段落或换行处截断，相邻窗口最多重叠约 150 字符。
这里使用字符长度，不是 token 数，也没有完整实现所有 Markdown 语法解析。

每块保留标题、章节路径、原文、相对文件路径和起止行号。
行号对应原始文本，支持 CRLF 换行；长单行的不同窗口可能引用同一行。

### 向量检索与存储

知识库使用 `qwen3-embedding:0.6b`，查询时使用面向文档的任务说明。
[Store](../jarvis/storage.py) 用 `knowledge_files` 和 `knowledge_chunks` 保存文件摘要、分块原文及向量。

检索先限定根目录和向量模型，再逐块计算余弦相似度，筛选阈值并取前 K 条。
它遵循当前项目的纯向量检索方式，没有关键词加权或文字检索回退。
片段通过工具交给聊天模型，引用字段为 `相对路径.md:L起始行-L结束行`。

## 6. 与会话上下文和联网搜索的关系

| 入口 | 来源 | 维护方式 |
| --- | --- | --- |
| `search_knowledge` | Markdown 目录 | 人工编辑原文件，程序同步索引 |
| `search_web` | 豆包搜索公开网页 | 每次请求时联网检索 |

知识库当前按目录共享，不同 `--user` 不会切换知识库权限；`--user` 仍用于分隔提醒。
个人长期记忆功能已于 2026-11-02 移除，旧记忆和向量表已清除，不再提供 `/memories` 或记忆工具。
当前会话上下文只保存在进程内存中，`/clear` 或退出后清除，不自动写入知识库。
模型没有编辑或删除知识库原文件的工具，只有检索入口；资料是参考数据，不应覆盖系统规则。

知识库服务默认通过本地 Ollama 计算向量，本身不调用豆包；修改 Ollama 服务地址后，计算位置随配置改变。
还需要用实际问题确认模型是否正确调用知识库，以及回答与引用是否符合资料。

## 7. 测试与当前范围

```powershell
.\wsl.ps1 -Action test
.\wsl.ps1 -Action kb-smoke
```

`kb-smoke` 用临时 Markdown 和内存数据库验证语义检索、模型引用、修改与删除同步，不改写用户资料。
该测试禁止调用联网搜索，不消耗搜索 API 额度。

当前范围：

- 文件需为 UTF-8，可带 BOM；单文件上限为 2 MiB。
- 只处理 Markdown 文本，不抓取文档里的网页链接，不进行图片 OCR，也没有 PDF/Word 导入。
- 同步要扫描目录，检索在 Python 中逐条比较向量，尚未使用 ANN 向量索引；大规模资料需要后续优化。
- 没有自动合并冲突、文件级授权或内容真实性判定，资料由你维护。

编码不正确、文件过大或向量模型不可用时，`/kb-sync` 和知识库查询会说明错误。
先用 `/kb` 确认目录，再用 `/kb-sync` 查看同步结果。

## 8. 短问题与来源选择

“海丽希斯镇的情报”曾出现模型先选联网搜索的问题。原文使用“海丽希思镇”，
实测两种写法都能通过向量检索命中 `henesys_plains.md`；该问题出在模型选择工具，而非子目录扫描。

系统提示词和工具说明现要求：地点、人物、组织、世界观和项目的介绍、情报或设定，
即使没有明确写“知识库”，也优先调用 `search_knowledge`；片段足够时依据原文回答。
明确要求联网或查询实时消息时仍使用 `search_web`。这属于模型的工具选择规则，
不是对任意问法的强制路由保证；如果仍选错，可明确提问“根据本地知识库，……”。

`Agent._knowledge_sources()` 检查本轮实际知识库结果。模型正文遗漏完整引用时，
程序追加“本轮知识库检索来源”，仅使用工具实际返回的文件与行号；已有完整引用时不重复追加，
也不把上一轮来源带到未检索的新一轮。来源列表便于核对，不等于自动验证了生成内容中的每条事实。

修改代码后需退出旧 CLI 并重新启动。知识库原文和向量不受这次工具选择规则调整影响，无需强制重建。
`kb-smoke` 已加入不带“知识库”字样的虚构城镇短问句，验证优先本地检索且不调用联网搜索。
